Hotjar Pattern Finder

Ask a question. Get an answer built from several real sessions — not one recording, a pattern. Works on any website or app you record with Hotjar.

The problem

One recording is an anecdote, not an answer.

Today
Watch → scrub → guess

Open a recording. Watch 10–15 minutes to find the moment that matters. Do it again for the next session — if you remember to, and if you have the time.

→
With the skill
Ask → sample → know

One question in. Several sessions sampled, jumped straight to the relevant moment, and cross-checked against each other before anyone calls it a pattern.

What it does

Give it a question. It gives you a pattern.

01

Samples, not one

Pulls 5–10 recordings from a filter or segment you've already saved in Hotjar — not a single lucky (or unlucky) session.

02

Jumps to the moment

Uses Hotjar's own rage-click, u-turn and error markers to go straight to what matters, instead of watching start to finish.

03

States its confidence

Reports "4 of 5 sessions," not a vibe — and says so plainly when there's too little evidence to call it a trend.

How it works

From question to report, in five steps.

1

Check the counts first

Reads each session's rage-click / u-turn / error tally before opening anything — skips sessions with nothing relevant.

2

Click the marker

Jumps straight to that timestamp on Hotjar's own timeline. No linear scrubbing through dead time.

3

Capture and caption

Screenshots the moment and writes the caption from Hotjar's own labeled event, not a guess.

4

Propose highlights, ask first

Suggests a short list of Hotjar highlight clips worth saving to the team's collection — nothing gets written until you approve it.

5

Synthesize into a report

Counts how many sampled sessions actually match, flags confidence, and writes it all into a Word doc with next steps.

Before you run it

Four things it needs from you.

GOAL
One sentence on why this matters right now. e.g. "we're deciding whether to redesign the checkout step"
QUESTION
The specific thing you want answered. e.g. "do users hesitate before clicking Pay?"
FILTER / SEGMENT
A filter or segment you've already saved in Hotjar. it won't build one from scratch — yet
SAMPLE SIZE
How many sessions to sample. defaults to 5, capped at 10
What it won't do

It rides your login. It never asks for your password.

🔒

Needs you already signed into Hotjar in Chrome. If it hits a login screen, it stops and asks you to sign in yourself — it will never touch a credentials field.

🔎

Recordings are real user and account data. The report is saved locally only — it always asks before sharing it anywhere, every time, even if a past run was approved.

⚖️

Fewer than 3 matching sessions? It calls that an anecdote out loud in the report, never a pattern.

💡

Highlights are writes to the team's shared Hotjar workspace. It proposes a list first and only saves after you say go — never edits or deletes a highlight it didn't create.

What you get back

A Word doc, backed by shareable highlight clips.

A .docx report — plus, evidence links open a Hotjar highlight clip of just that moment, not a raw timestamp.

Get it running

A few minutes, then it's yours.

Install it as a Claude Code plugin. Updates arrive with one command.

In Claude Code
/plugin marketplace add jaytran-prog/Hotjar-pattern-finder
/plugin install hotjar-pattern-finder@hotjar-pattern-finder

Restart Claude Code if the skill doesn't show up. On first use it runs a setup check and installs the one npm package it needs.

You also need

Claude in Chrome extension, connected to Claude Code — and signed in to Hotjar in that Chrome.

Python 3 + Pillow (screenshots) and Node 18+ (Word report). The setup check tells you exactly what's missing.

1 Run the two commands above in Claude Code.
2 Make sure you have a saved segment in Hotjar for what you want to study.
3 Ask your question. Full guide: github.com/jaytran-prog/Hotjar-pattern-finder
